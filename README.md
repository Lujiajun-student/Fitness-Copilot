# Fitness Copilot

Fitness Copilot 是一款 AI 驱动的个性化运动健康管理系统。用户完成注册、登录和身体档案录入后，可以直接向 AI 助理说明目标，例如“未来一个月减脂”或“提高跑步耐力”。系统将结合用户身体状态、训练历史和安全约束，生成未来一个月按天拆分的训练计划与三餐饮食计划。

> 当前项目将从头开发。本 README 描述的是新的产品需求和目标架构，而非旧代码的运行说明或实现状态。

## 核心用户流程

1. 用户注册并登录系统。
2. 用户填写或更新身体档案，例如年龄、性别、身高、体重、体脂率、围度、训练经验、伤病史和可训练时间。
3. 用户向 AI 助理描述目标，例如减脂、增肌、提高力量、提高耐力或改善体能。
4. 系统基于目标和档案生成未来一个月的计划：每天的训练安排，以及早餐、午餐、晚餐。
5. 用户查看、确认或调整计划，并在每天训练或进食后记录实际完成情况。
6. 系统根据用户记录、体重变化和恢复状态，后续重新评估并调整未执行的计划。

## 用户功能

### 注册、登录与账户

- 用户可以注册、登录和安全退出。
- 登录后只能查看和修改自己的身体档案、训练记录和计划。
- 系统应安全保存密码，不保存明文密码；受保护接口需要身份认证。

### 身体数据录入

用户可录入并持续更新：

- 基础资料：年龄、性别、身高、体重。
- 身体指标：体脂率、胸围、腰围、臀围等。
- 健康与训练背景：训练经验、既往伤病或禁忌、当前运动习惯。
- 计划偏好：可训练日期和时段、可使用的器械、饮食偏好或忌口。

这些数据是生成个性化计划和执行安全校验的必要依据。

### AI 助理与目标咨询

用户可以自然语言提出需求，例如：

> 我希望接下来一个月减脂，每周可以训练五天，工作日晚上和周末上午有时间。

AI 助理应在信息足够时直接生成计划；如果缺少会影响安全性或可执行性的关键资料，应先追问，例如伤病情况、训练经验、可用器械和饮食限制。

### 一个月训练计划

系统为未来连续一个月生成按日拆分的训练计划。每一天至少包含：

- 当日训练目标与训练类型，例如力量、有氧、恢复或休息。
- 具体时间段与动作安排。
- 每个动作的组数、次数或时长、建议重量/强度、组间休息。
- 当日有氧内容，例如距离、配速或心率区间。
- 热身、放松和恢复提示。
- 计划状态：待确认、已确认、已完成、跳过或需要调整。

示例（实际内容必须随用户能力动态变化）：

```text
第 1 天：下肢力量与低强度有氧
09:00–09:10  动态热身
09:10–09:40  深蹲：5 组 × 25 次，组间休息 10 分钟
09:40–10:00  恢复与补水
10:00–10:30  哑铃弯举：5 组 × 30 次，组间按能力休息
下午        依据当日身体状态安排有氧或恢复训练
```

以上仅是展示格式，不是默认训练处方。动作、重量、次数、组数、休息时间和训练频率必须由用户能力、训练历史、恢复状态和安全规则共同决定。

### 一个月三餐饮食计划

在训练计划确定后，系统为同一周期内的每一天生成早餐、午餐和晚餐计划。每餐至少包含食材、建议份量、营养估算和替换建议。

示例：

```text
第 1 天午餐：菠菜 300 g、瘦猪肉 150 g、米饭 100 g
```

饮食计划需体现每日目标热量、蛋白质、碳水化合物和脂肪的分配，并根据训练日、休息日和用户忌口调整。它提供健康管理建议，不替代医生、营养师或其他专业医疗意见。

### 训练、饮食记录与每日总结

- 用户可记录实际完成的有氧训练、力量训练和主观疲劳感。
- 用户可记录实际饮食或标记计划餐是否完成。
- 系统汇总当天训练量、饮食摄入、计划完成度和身体状态，生成健康日记与次日建议。

## AI 计划生成工作流

系统采用多 Agent 协作，而不是由单一模型直接输出计划。

```text
用户目标与身体档案
        ↓
规划 Agent：建立一个月目标、周期和每日框架
        ↓
力量 Agent ⇄ 体能 Agent：讨论并修订每天的训练方案
        ↓
Harness 安全层：校验训练负荷、恢复和热量风险
        ↓
营养 Agent：依据已通过的每日训练生成一个月三餐计划
        ↓
用户确认、执行与记录
```

### 规划 Agent

负责理解用户目标，整合身体档案与可训练时间，建立未来一个月的周期框架，包括训练日、休息日、力量训练、有氧训练和恢复日的分布。

### 力量 Agent

负责提出力量训练与渐进超负荷方案，包括动作选择、组数、次数、强度、间歇和训练容量。它可以利用用户历史训练记录和 1RM 等工具评估合适负荷。

### 体能 Agent

负责评估心肺、耐力、疲劳和恢复需求，提出有氧与恢复建议，并对不合理的强度、频率或训练组合提出修改意见。

### 力量 Agent 与体能 Agent 的协商

两个 Agent 针对每日计划进行有限轮次的协商：力量 Agent 关注训练刺激与进步，体能 Agent 关注心肺能力、恢复和可持续性。规划 Agent 汇总意见并形成一致方案；若无法达成一致，或达到协商上限，则采用更保守的方案并交由 Harness 校验。

### 营养 Agent

在训练计划通过安全校验后，按每日训练负荷、用户身体数据、目标热量和饮食限制，为一个月中的每一天生成早餐、午餐和晚餐，并提供可替代食材。

## Harness 安全层

Harness 是确定性的安全与约束层，优先级高于 Agent 的生成结果。原则是：宁可降低训练目标，也不输出可能导致明显伤害风险的建议。

至少应校验：

- 训练强度、容量和频率是否与用户经验及近期训练量相符。
- 是否连续训练相同肌群，或恢复时间不足。
- 是否存在超过合理上限的重量、次数、心率或耐力负荷。
- 减脂计划的热量缺口是否过大，营养是否明显失衡。
- 是否命中用户记录的伤病、禁忌或医疗风险。

校验失败时，系统不得直接展示原计划；应给出原因和可执行的修改方向，要求相关 Agent 重新生成。对于高风险或接近个人极限的方案，应要求用户明确确认，并提示其寻求专业人士意见。

## 数据与服务边界

首期需要管理的核心数据包括：

- 用户账户和身份认证信息。
- 用户身体档案、健康限制和训练/饮食偏好。
- 有氧与力量训练记录。
- 一个月计划、每日计划及其状态流转。
- 每日三餐饮食计划、实际摄入和营养统计。
- Agent 生成、协商和 Harness 校验的结果，便于追溯。

后续可加入运动医学、运动营养、康复和运动生理学知识库，为 Agent 提供可检索的参考资料；用户私有数据与通用知识库应严格隔离。

## 首期交付范围

第一阶段优先实现以下闭环：

1. 注册、登录与用户身体档案。
2. 用户以自然语言提交目标。
3. 基于档案生成一个月、按日展示的训练与三餐计划。
4. 力量 Agent、体能 Agent、营养 Agent、规划 Agent 的基础协作流程。
5. 训练负荷、恢复和热量风险的基础 Harness 规则。
6. 用户记录每日完成情况，并获得每日总结与后续计划调整建议。

微服务拆分、RAG 知识库、复杂自动化任务、完整可观测性和 CI/CD 可在核心闭环验证后逐步建设。
